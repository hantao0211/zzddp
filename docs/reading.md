# 课外阅读、成长与家庭奖励

当前按一个家庭、一个孩子设计，共用现有登录与角色。学习首页提供“课外阅读”“成长与奖励”，地址分别为 `/reading/` 和 `/reading/?view=growth`；家长后台可进入“阅读与奖励”，家长在阅读页“家长设置”配置规则、奖励和审批。

## 孩子每天的流程

1. 首次填写书名添加书籍，可选按书名或ISBN查询公开书目信息，核对作者、出版社与版本；查不到或服务不可用时直接填写，之后从书架选择。
2. 记录日期、开始/结束页、分钟数，用几句话概括今天读到什么；可计时或录制最多30秒语音并转文字，提交前可修改。
3. 保存即完成打卡和小脚步计算，AI在后台评价，不等待模型。一次阅读保存为一个记录，同一天分几次读可以分别记录并累计时长；只有第一次符合条件的提交获得基础小脚步。
4. 可修改自己录入的记录，家长可修改所有记录；版本检查避免覆盖其他设备的新改动，重试同一提交不重复发放小脚步。历史支持按日期、书籍筛选和分页。

计时采用本设备开始/结束时刻，可在同一浏览器返回后恢复，不证明一直在有效阅读。时长可手动调整；同一天的分钟数累计，书架页数按覆盖页码去重，累计阅读页数包含重读。书架“已读完”由家庭标记，不冒充系统已验证理解全书。

## AI评价依据

查书服务使用Google Books公开书目信息，查询仅发送书名或ISBN，不发送孩子的概括、个人资料或书页。简介、模型记忆和书名都不能作为章节原文。不是所有书都有公开资料，也不保证取得全文或对应版次内容。

相关原文或一张书页照片可选填。照片在浏览器转为不超过1600边长的JPEG，服务端限制2MB、私有保存，按现有AI服务配置发送进行本次评价，原图只通过已认证接口读取；录音使用现有语音服务，不长期保存音频。评价只比较提供的片段，不核验整段页码或全书，不剧透。没有依据、照片不清或模型没有给出可核对引用时，程序强制标明“内容准确性暂未核对”。表达反馈、一个小问题和建议可照常提供，不按概括字数、快慢给能力标签或扣小脚步。

阅读交流使用独立的阅读上下文和实际记录，不把语文作业、旧课号或学习清单混入阅读对话。聊天不能保存记录、发小脚步、配置规则或批准兑换；这些操作均由固定API和角色验证执行。

## 连续打卡与小脚步

按北京时间统计，不能提交未来日期，最多补记过去一年。同一天最多20次记录。默认每日2个小脚步，连续3/7/14/30天额外3/10/20/50个小脚步；家长可调整，最多8个连续目标。默认补记保留阅读记录，但不补领基础或连续奖励；家长可允许之后提交的补记参与奖励。规则用于后续提交，已发放小脚步不因断签、修改记录或改规则消失；同日重复提交和修改不会重复发放小脚步。阅读质量评价与小脚步计算分开，AI没有发放小脚步权限。

小脚步账本保留日期、原因、规则事件键与操作者，基础分以日期唯一，连续奖励以达成日期与目标唯一。记录、小脚步和任务入队在SQLite事务内完成；重试不会重复计费。

## 家庭商城

家长添加、编辑或停用奖励，孩子用可用小脚步申请。申请在事务内暂扣小脚步，固定请求ID重试不重复扣小脚步；家长可同意或取消，取消只返还一次。实际奖励兑现后标记“已兑现”，该状态不再退款。奖励名称与价格在申请时留快照，之后调价不影响旧申请。界面展示待确认、待兑现、已兑现或已取消及小脚步明细。

## 孩子的心愿

“成长与奖励”先显示脚印图标与小脚步余额，然后是“我的心愿”和家庭商城；阅读统计与连续目标收在展开详情里。孩子点“我要许愿”，填一个心愿名称，可选补一句想法，直接送给家长，不扣小脚步。待处理心愿显示时钟与“等家长看看”，本人可撤回；首页只展示一个最近待处理或新处理的心愿，其他心愿与兑换历史默认收起，兑换摘要直接显示待家长确认的数量。

家长设置顶部显示待处理心愿和数量。审批时保留孩子的原话，家长可调整商城名称、约定说明、兑换所需的小脚步及给孩子的话。“通过并加入商城”在同一事务内生成一个启用的商城奖励并关联心愿；孩子攒够小脚步后再走已有兑换审批流程，不会因为许愿通过直接扣除或发放奖励。“这次先等等”必须写一句给孩子的说明，孩子看到“家长有话说”，不作为惩罚。

固定请求ID避免网络重试重复许愿；审批内容摘要与状态检查避免重复上架或覆盖另一位家长的处理。孩子不能审批、定价、伪造提交人或修改状态；仅本人可撤回未处理的心愿。最多20个待处理、1000个心愿历史；商城100项上限同样适用，满额审批整体回滚，原心愿保留待处理。家长日后仍可修改或暂停通过心愿创建的商城奖励。

界面奖励单位统一为“小脚步”，余额、价格、额外奖励和明细搭配脚印图标。已有账本和数额不迁移、不清零；旧账本说明含“积分”时只在读取展示层替换名称，原记录保留。小助手了解许愿和兑换入口，但聊天不能替代审批或直接发放小脚步。

## 维护与边界

私有数据单独保存在 `ASSISTANT_STATE_DIRECTORY/reading/reading.sqlite` 和 `reading/images/`，不修改原作业档案。WAL与FULL同步，后台评价任务持久化、版本检查，重启恢复；每日最多20次评价调用，自动重试至多2次，人工重试合计最多3次。额度耗尽的任务保留排队，后续继续；失败不丢打卡和小脚步。图书查询每日最多40次，服务不可用可手工添加。照片空间限制200MB，书架最多500本，阅读记录最多20000条。

首次发布不预置真实书籍、阅读记录或虚构小脚步、奖励；家长添加第一项家庭奖励后，孩子即可兑换。没有全书获取承诺、阅读质量总分、自动判断孩子是否认真、实物配送或跨家庭隔离。

备份和迁移应包含整个私有状态目录。回退旧代码时保留新阅读目录，不能用旧备份覆盖新增阅读、小脚步或兑换记录。源码、文档和测试不包含真实家庭资料或密钥。

图书检索服务不可达时会明确提示手动添加；不会用模型生成的书目信息冒充检索结果。已保存的历史记录超过一年后仍可修改原记录，但不补领过去的小脚步。

### 每天完成作业奖励

从功能启用的上海日期起，系统确认某个作业日期的整天清单全部做完，按家长设置自动奖励“小脚步”（默认1个）。依据是当日最新备忘录的完整清单、对应范围的照片，以及书面作答检查/预习复习学习痕迹；空清单、未归类条目、正在整理、缺页、未做完、无法判断或旧版检查不会发奖。不要求答案全部正确，不等待批改结束；仅有照片或备忘录打勾不算完成。

后台每5秒检查已整理结果，不通过聊天或客户端直接发放。奖励使用现有ledger，唯一事件`homework:作业日期`、kind=homework，按尚未发放时的家长设置发放；事务保存奖励和审计。重复上传、修改、重新整理、页面刷新、服务重启都不会重复发放，临时入账失败会重试。迟到的整理结果按原作业日期计一次；启用日前的档案不追溯补发。已发出的鼓励不因后来修改清单而自动扣回。

作业奖励与阅读奖励共用余额、累计获得和家庭商城，不影响阅读打卡、连续天数或阅读奖励规则。首页显示发奖规则/到账状态，成长页显示规则和入账明细。后台会持久保存启用日期`settings.homework_reward_start`，不新增数据库表。


家长在“家长设置 → 作业完成奖励”可设置每日0～100个小脚步，0表示关闭，默认1。`PATCH /assistant-api/reading/homework-rules` 仅家长/家庭管理员可调用，且需家庭登录及同源检查；规则单独保存在`settings.homework_reward_rules`并记录审计，与阅读奖励独立。更改适用于启用日期以来尚未发放的作业奖励；重新启用后会重新检查这些日期，已发过的日期不追加、不扣回。首页已到账提示始终显示实际发放数量，成长页显示当前规则。家长未保存的输入不会被后台定时刷新覆盖，保存失败仍保留输入。

状态：当前已运行单家庭 TypeScript／Next.js／Node.js 服务，使用 SQLite、私有文件存储和后台队列，接入真实识别、批改与小助手。下文技术表是扩展方案，尚未实施的组件不能视为当前依赖。更新日期：2026年11月20日。

## 技术选型

| 部分 | 建议方案 | 用途 |
| --- | --- | --- |
| 前端 | TypeScript、React、Next.js | 孩子端与家长端页面、拍照上传、进度反馈和打印入口 |
| 接口 | Next.js Route Handlers，运行于 Node.js | 登录、权限、资料与任务接口，共用类型和业务模块 |
| 数据库 | PostgreSQL + Prisma | 家庭、权限、作业、题目、批改历史和积分流水 |
| 原件存储 | 私有 S3 兼容对象存储 | 保存照片、扫描件及练习 PDF，数据库保存索引与关联 |
| 后台处理 | 独立 Node.js worker + pg-boss | 持久化队列、识别、批改、生成练习、复测和周报 |
| PDF | HTML 打印模板 + Playwright Chromium | A4 排版、题目与作答区、任务二维码，配置中文字体及公式渲染 |
| 家庭打印连接 | 优先验证 Node.js 打印代理 + 设备打印系统 | 家中设备主动取任务并向本地打印机发送文件，具体取决于设备 |
| 部署 | Docker Compose | 网站、后台任务和数据库部署；对象存储可用托管服务 |

前后端与后台任务共用 TypeScript，分别运行网页服务与后台 worker，避免识别任务阻塞网页请求。第一版使用 PostgreSQL 持久化任务队列，减少额外运行组件。未来确有本地图像算法需求时再引入 Python 服务。

## 资料处理

1. 服务端验证身份与家庭权限，为上传创建资料记录和短期上传凭证。
2. 原件写入私有对象存储，服务端确认文件存在后创建处理任务。
3. worker 进行页面方向与清晰度检查，识别版面、题目、作答与批改，保留原图坐标。
4. 将识别结果转换为带字段校验的结构化数据，匹配备忘录和任务。
5. 按题型调用批改流程，记录老师判断、系统判断、依据与版本。
6. 存储结果并更新任务状态，前端读取进度；失败任务可重试，重复提交不重复建账。

模糊到缺少必要信息时，提示重新拍摄对应页面；这与要求家长逐题核对不同。无法恢复的信息不猜填。

## 识别与批改

采用可替换的 OCR 和视觉语言模型服务接口，提供商通过代表性样本、费用和数据处理要求验证后确定。系统 API 密钥只保留在服务器。

备忘录识别与试题批改分开处理。先提取题目与作答，再进行规则和解题校验，避免只让模型看图给出一个总分。

确定可形式化的计算题优先使用精确数值、分数或规则检查；应用题和步骤分析结合模型处理，并保留依据。几何图形、单位、等价答案和开放题按实际验证能力逐步支持。

题目生成与答案验证分开，生成的练习先检查题意、答案和解析再发布。模型结果或置信分数不能直接当作事实；师生批改分歧与识别不清有各自状态，暂不纳入确定结论。

## 学习安排

第一版以可解释规则安排复习：结合知识点、近期错误和复测情况选择任务，学校作业优先，控制额外练习量。模型辅助讲解和生成变式，系统规则负责权限、进度和积分。

先用数据库查询完成趋势和知识点统计，暂不依赖向量数据库或自训练模型。

## 一键打印

候选流程：孩子点击打印 → 服务端生成 PDF 并建立打印任务 → 家中常开设备的代理经 HTTPS 主动领取任务 → 本地打印系统发送 → 回传可获得的状态。

Linux 或兼容设备可验证 CUPS/IPP 路径；Windows 需验证对应驱动和打印适配。若打印机有可用的厂商接口，也可采用直接集成。

代理使用仅限本家庭打印任务的设备凭证，不需要从公网开放家中端口。为打印任务保存唯一编号及本地发送记录；发送状态不明时先核实，不能盲目重试导致重复打印。已提交到打印队列与纸张实际打印完成分开显示。

此方案依赖兼容打印机和在线的家庭设备。若没有常开设备，需要验证厂商云打印、独立打印盒子或应用方案；型号未确认前不能保证直接打印。打开系统打印对话框作为回退入口，需明确显示其操作方式。

## 部署与数据维护

建议首先采用一台可长期运行的服务器和私有对象存储，网站经 HTTPS 访问，家中仅运行需要的打印代理。具体地区和托管服务依据访问条件、预算及资料处理要求确定。

公开代码仓库只存代码、文档和模拟数据。学习原件、数据库备份、模型密钥与设备凭证不得提交。账号登录、权限及家庭隔离由服务器校验，不能只通过前端隐藏按钮实现。

数据库与原件分别备份并验证恢复。重要判断、积分及兑换保留修改记录。备份策略和保留周期在试运行前确定。

## 实施顺序

1. 建立 TypeScript 项目和可点击页面，使用明确标记的模拟数据。
2. 接入 PostgreSQL、账号权限和私有原件存储，跑通备忘录与作业归档。
3. 接入 worker 和模型服务，以数学代表性材料验证完整处理流程。
4. 实现练习 PDF、回传匹配和家庭打印代理，实机验证。
5. 增加复测、家长周报和简单奖励，再按实际反馈扩展。

## 跨端实现约定

第一版为自适应网站；后续优先评估 Capacitor 打包手机与平板应用。共享后台接口、数据模型和业务规则；相机、文件选择、通知和打印通过平台适配接入。Next.js 的服务端功能继续部署于服务器，不随 App 一同打包。

现有 `LearningGateway` 定义读取、保存和原件访问方式；浏览器原型实现仅用于演示，未来替换为通过登录和家庭授权的 HTTP 接口。原型里的视角切换不具备真实账号隔离能力。

若将来需要原生手写和复杂扫描能力，再评估专门的原生界面；不能承诺所有网页组件直接复用于原生界面。

## AI与语音的交付顺序

备忘录作为作业清单依据；孩子端取消科目和任务必填选择。后台通过可替换视觉模型自动拆分、分科、关联和查缺，出题必须另行校验。采用上传触发整理与定时复盘备题的混合模式，界面读取已保存结果；小助手文字及语音问答实时响应。

模型适配、私有上传、持久化队列、家庭访问码、HTTPS、识别、批改和小助手已接通；独立成员账号与完整权限、家庭打印代理仍待实施。完整状态见 [后台AI与小助手工作流](ai-workflows.md)。

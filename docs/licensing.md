# 使用许可说明

本项目采用根目录的[小步学习源码使用许可协议 1.0](../LICENSE)。本文便于阅读，不替代正式协议；有出入时以 `LICENSE` 中文文本为准。

| 场景 | 按本协议如何使用 |
| --- | --- |
| 家庭自托管、个人学习、非商业研究 | 可以使用及修改；私人修改无须公开 |
| 非商业教学或公益使用 | 可以使用，须符合协议中的非商业定义 |
| 改成收费网站、订阅产品、SaaS、商业 API | 相关商业项目前后端及部署代码须整体公开，不能只公开上游原代码 |
| 帮客户收费部署、定制交付、维护 | 属于商业使用，须履行整体源码公开义务 |
| 商业公司内部业务系统 | 商业使用也受约束，不能仅以没有对外分发为由豁免 |
| 同一公司不相关的软件项目 | 不因此必须公开 |
| 儿童照片、学习记录、密钥和生产数据库 | 不得作为源码公开；用模拟数据和配置模板替代 |
| 第三方库和托管模型服务 | 保留其原许可；公开自有集成代码，不要求取得其内部源码 |

## 商业项目如何满足条件

1. 在首次商业开发、交付、运行或内部部署中的最早一项之前，建立可免费匿名读取的公开源码仓库，发布当时已有的完整相关项目。
2. 开发中未使用的改动至少每三十日公开一次；任何已交付或运行版本的对应源码须在开始使用该版本时同步公开。
3. 自有或有权授权的相关代码使用同一份协议；第三方代码保留原许可证和声明。
4. 包括前后端、业务模块、接口、数据库结构与迁移、依赖清单、构建及部署模板、必要说明，不能只发编译包或上游原始分叉。
5. 软件或服务中提供指向实际对应源码的显著链接；停止提供版本后仍保持其源码公开至少三年。

不能满足这些条件时，本协议不许可相应商业使用。单独书面授权必须覆盖实际涉及的权利人，不能假定维护者能够代替所有贡献者和第三方授权。

## 为什么没有直接选择 AGPL

AGPL 允许商业使用，通过其规定的传播、组合及网络交互条件要求提供相应软件源码。它不等于“商业公司必须公开所有项目”，也不是“禁止商业开发”的许可证。这里的自定义协议进一步要求相关商业项目整体公开，且涵盖商业内部使用，所以不冒称标准 AGPL。

本项目应称为“源码公开／源码可用，商业使用附条件”。本协议不声称符合 OSI 的开源定义。GitHub 对自定义协议可能只显示未识别或其他类型；不能通过把元数据写成 MIT 或 AGPL 来解决。

## 边界与执行

自定义条款的可执行性、相关商业项目范围及第三方兼容性，仍须结合实际情况和适用法律判断；不能承诺仅凭本文件就能自动取得对方全部源码或保证胜诉。正式商业争议及重要合作宜由知识产权律师审核。

本协议不要求贡献者转让著作权，也没有因提交一个 PR 就新增独立的贡献者协议；提交时应清楚确认许可意愿、权属和第三方来源。
